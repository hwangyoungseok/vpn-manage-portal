# RemoteHub 화면 목업

VPN 관리 서비스 **RemoteHub**의 화면을 그려 합의하기 위한 디자인 프로토타입입니다.

> **제품 코드가 아닙니다.** 제품 구현은 ASP.NET Core MVC + Razor View로 별도 진행하며,
> 이 목업은 레이아웃·정보 구조·상태 표현을 확인하는 용도로만 참조합니다.
> React는 이 디렉터리 밖으로 나가지 않습니다. — `PLAN.md` Phase 0

데이터는 전부 `src/data/mock.ts`의 인메모리 더미이고, 백엔드·DB·외부 연동은 붙어 있지 않습니다.
버튼을 눌러도 저장되거나 전송되는 것은 없습니다.

## 실행

Vite 8 요구사항에 따라 **Node 20.19+ 또는 22.12+**가 필요합니다 (개발은 Node 26에서 했습니다).

```bash
cd mockup
npm install
npm run dev      # http://localhost:5173
```

| 명령 | 설명 |
|------|------|
| `npm run dev` | 개발 서버 (HMR) |
| `npm run build` | 타입 검사(`tsc -b`) 후 프로덕션 빌드 → `dist/` |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run lint` | oxlint |

로그인 화면은 아무 값이나 넣어도 통과합니다. 우측 상단 아이콘으로 라이트/다크 테마를 전환합니다.

## 화면

| 경로 | 화면 | 요구사항 |
|------|------|----------|
| `/login` | 로그인 (ID·비밀번호 → MFA 2단계) | §9 §10 |
| `/` | 대시보드 — 계정 수, 만료 임박, 신청 대기, 잠김 계정 | — |
| `/requests` | 신청 목록 — 필터, 일괄 선택, 엑셀 업로드 | §2 |
| `/accounts` | 계정·정책 목록 — 검색·필터, 엑셀 다운로드 | §3 |
| `/accounts/:id` | 계정 상세·정책 편집 — 기존 ACL 매핑 / 새 ACL 생성 | §1.2 |
| `/companies` | 그룹사 관리, 그룹 ACL | §4 |
| `/ip-ranges` | 그룹사별 IP 대역, 고정 IP 할당 | §5 §6 |
| `/deleted` | 삭제 사용자 — 삭제 사유 구분 | §8 |
| `/reports` | 월간 리포팅 — 회사별 현황, 변경 관리 현황 | §12 |

사이드바의 **관리** 그룹:

| 경로 | 화면 | 요구사항 |
|------|------|----------|
| `/admins` | 관리자 — 계정 목록, 추가 · 수정 모달, 잠김 해제 | §9 |
| `/permissions` | 권한 — 역할 정의, 권한 매트릭스 | §9 |
| `/audit` | 감사 로그 — 관리자 행위 내역 | §11 |

관리자 추가 · 수정과 엑셀 업로드는 모달입니다. 추가 · 수정 · 잠김 해제는 화면 state에만
반영되며 새로고침하면 초기 더미 데이터로 돌아갑니다.

비밀번호 입력란은 요구사항 §9의 규칙(8자 이상 + 소문자 · 대문자 · 숫자 · 특수문자 중 3종 이상)을
실시간으로 검사하고, 통과 전까지 저장 버튼을 막습니다.

요구사항 번호는 [`docs/00-requirements.md`](../docs/00-requirements.md)의 장 번호입니다.

## 구조

```
src/
  data/mock.ts              더미 데이터 (계정·정책·그룹사·IP·로그)
  lib/format.ts             이름 마스킹 등 표시 규칙
  components/layout/        앱 셸(사이드바·헤더·테마), 페이지 헤더
  components/status-badge   상태·구분·결과 배지
  components/ui/            shadcn/ui 컴포넌트 (생성물, 직접 수정 지양)
  pages/                    화면별 컴포넌트
```

## 스택

Vite · React 19 · TypeScript · Tailwind CSS v4 · shadcn/ui · React Router · Recharts

**shadcn v4는 Radix가 아니라 [Base UI](https://base-ui.com) 기반입니다.** 컴포넌트를 추가할 때 주의할 점:

- `asChild` 대신 `render` prop을 씁니다 — `<Button render={<Link to="/x" />}>라벨</Button>`
- `Select`의 `onValueChange`는 `string | null`을 넘깁니다 — `(v) => setX(v ?? 'all')`
- 카드 헤더의 우측 액션은 `CardAction` 슬롯에 넣습니다

## 개인정보 표시 규칙

요구사항 §10에 따라 사용자 이름은 가운데를 마스킹해 표시합니다 (`김민수` → `김*수`).
엑셀 다운로드에서는 이메일·전화번호 등을 제외하고 계정·정책·만료 기한만 포함한다는 안내를
계정 목록 화면에 표시해 두었습니다. 실제 마스킹·제외 로직은 제품 구현에서 서버 측에 둡니다.

## 차트 색

shadcn 기본 `--chart-1..5`는 채도 0인 무채색 램프라 범주를 구분할 수 없어 교체했습니다.
라이트/다크 각각의 값은 `src/index.css` 하단에 있으며, 명도 밴드·채도 하한·색각 분리·대비 검사를
두 모드 모두 통과한 조합입니다. 색을 바꿀 때는 아래를 지켜 주세요.

- 범주 색 순서는 고정이며 순환시키지 않습니다.
- **파랑과 보라를 인접 배치하지 마세요.** 적록색약에서 거의 구분되지 않습니다(ΔE 0.4).
  막대 스택 순서를 바꿀 수 없는 이유가 이것이고, 그래서 합계를 축 라벨로 뺐습니다.
- 척도가 다른 지표는 축을 공유하지 않습니다. 전체 계정 수와 월간 신규·삭제를 별도 차트로 나눈 이유입니다.
