# RemoteHub 화면 목업

VPN 관리 서비스 **RemoteHub**의 화면을 그려 합의하기 위한 디자인 프로토타입입니다.

> **제품 코드가 아닙니다.** 제품 구현은 ASP.NET Core MVC + Razor View로 별도 진행하며,
> 이 목업은 레이아웃·정보 구조·상태 표현을 확인하는 용도로만 참조합니다.
> React는 이 디렉터리 밖으로 나가지 않습니다. — `PLAN.md` Phase 0

데이터는 `src/data/mock.ts`의 더미 데이터로 시작하고, 관리자·ACL·계정 정책·감사 로그의
변경 내역은 브라우저 `localStorage`에 저장합니다. 백엔드·DB·VPN·AD 연동은 없습니다.

## 실행

Vite 8 요구사항에 따라 **Node 20.19+ 또는 22.12+**가 필요합니다 (개발은 Node 26에서 했습니다).

```bash
cd mockup
npm install
npm run dev      # http://localhost:5173
```

| 명령 | 설명 |
|------|------|
| `npm run dev` | 개발 서버 (HMR) |
| `npm run build` | 타입 검사 후 `dist/index.html` · `index.js` · `index.css` 생성 |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run lint` | oxlint |

로그인 화면은 아무 값이나 넣어도 통과합니다. 우측 상단 아이콘으로 라이트/다크 테마를 전환합니다.

## HTML 파일로 열기 · 전달

개발 환경에서 한 번 빌드합니다.

```bash
cd mockup
npm run build
```

빌드 결과는 아래 세 파일입니다. HTML은 별도 JS·CSS 파일을 상대 경로로 읽습니다.

```text
dist/
  index.html
  index.js
  index.css
```

**세 파일을 같은 폴더에 둔 채 전달하고, `dist/index.html`을 더블클릭해서 엽니다.**
열람하는 사람에게 Node.js 설치나 웹서버 실행은 필요하지 않습니다. 폴더를 옮겨도 상대 경로로
JS·CSS를 읽으며, 폰트는 CSS에 포함되어 외부 CDN이나 별도 폰트 파일이 필요하지 않습니다.
소스의 `mockup/index.html`은 Vite 개발용 진입점이고, 직접 열어서 사용하는 파일은 빌드한
`mockup/dist/index.html`입니다.

화면 이동은 해시 라우팅을 사용합니다. 관리자 화면 주소는 `index.html#/admins`,
계정 상세는 `index.html#/accounts/A001`이며, 해당 화면에서 새로고침해도 그대로 열립니다.
`npm run dev`와 `npm run preview`도 같은 `#/...` 경로를 사용합니다.

Chrome에서 파일 직접 열기, 관리자·ACL 저장 후 새로고침, 모든 화면, 라이트/다크 표시를
확인했습니다. 저장 데이터는 브라우저 저장소에 남으며 JS 파일 자체에 기록되지는 않습니다.
개발 서버 주소와 파일 주소의 저장소는 별개이고, 파일 위치를 옮기면 기존 저장 데이터가
따라가지 않을 수 있습니다.

## 화면

| 경로 | 화면 | 요구사항 |
|------|------|----------|
| `/login` | 로그인 (ID·비밀번호 → MFA 2단계) | §9 §10 |
| `/` | 대시보드 — 계정 수, 만료 임박, 신청 대기, 잠김 계정 | — |
| `/requests` | 신청 목록 — 필터, 일괄 선택, 엑셀 업로드 | §2 |
| `/accounts` | 계정·정책 목록 — 검색·필터, 엑셀 다운로드 | §3 |
| `/accounts/:id` | 계정 상세·정책 편집 — 기존 ACL 매핑 / 새 ACL 생성 | §1.2 |
| `/companies` | 그룹사 관리, 그룹 ACL | §4 |
| `/ip-ranges` | 그룹사별 IP 대역, 고정 IP 할당 | §5 §6 |
| `/deleted` | 삭제 사용자 — 삭제 사유 구분 | §8 |
| `/reports` | 월간 리포팅 — 회사별 현황, 변경 관리 현황 | §12 |

사이드바의 **관리** 그룹:

| 경로 | 화면 | 요구사항 |
|------|------|----------|
| `/admins` | 관리자 — 계정 목록, 추가 · 수정 모달, 잠김 해제 | §9 |
| `/permissions` | 권한 — 역할 정의, 권한 매트릭스 | §9 |
| `/audit` | 감사 로그 — 관리자 행위 내역 | §11 |

관리자 추가 · 수정과 엑셀 업로드는 모달입니다. 관리자 추가 · 수정 · 삭제 · 잠김 해제,
그룹 ACL 추가 · 수정 · 삭제는 저장되며 새로고침하거나 다른 화면으로 이동해도 유지됩니다.

계정 상세에서 기존 ACL을 매핑하거나 새 ACL을 생성할 수 있습니다. 복수 목적지와 포트를
입력하고, **변경 사항 적용**을 누르면 ACL 생성과 계정 정책을 함께 저장합니다.
저장 전 화면을 떠나면 편집 중인 변경은 사라집니다. ACL 이름 변경은 기존 매핑에도 반영하며,
사용 중인 ACL은 계정 정책에서 매핑을 제거한 뒤 삭제할 수 있습니다.

관리자·ACL 이름 중복과 IP/CIDR·포트 형식을 검사합니다. 관리자·ACL·정책 변경 내역은
감사 로그에 기록하며, 마지막 Admin 관리자의 삭제와 운영자로의 역할 변경은 막습니다.
로그의 수행자는 목업의 고정 관리자(홍길동), IP는 `127.0.0.1`입니다.

저장 데이터는 **같은 브라우저와 같은 접속 주소(포트 포함)**에서만 유지됩니다.
여러 탭의 저장 변경은 화면에 반영되지만, 다른 브라우저나 사용자와 공유되지 않습니다.
사이드바의 **목업 데이터 초기화**를 누르면 관리자·ACL·계정 정책·감사 로그를 기본 데이터로
되돌릴 수 있습니다. 저장소 읽기·쓰기 실패는 화면에 표시하고, 저장 실패 시 성공 처리하지 않습니다.

나머지 신청·그룹사·IP·다운로드·기간 연장 등의 동작은 기존 화면 목업 범위입니다.
로그인과 MFA는 단계 전환만 보여주며, 추가한 관리자 계정으로 실제 인증하지 않습니다.

비밀번호 입력란은 요구사항 §9의 규칙(8자 이상 + 소문자 · 대문자 · 숫자 · 특수문자 중 3종 이상)을
실시간으로 검사하고, 통과 전까지 저장 버튼을 막습니다.
비밀번호는 입력 검증에만 사용하며 저장소나 감사 로그에 기록하지 않습니다.

요구사항 번호는 [`docs/00-requirements.md`](../docs/00-requirements.md)의 장 번호입니다.

## 구조

```
src/
  data/mock.ts              더미 데이터 (계정·정책·그룹사·IP·로그)
  data/mock-store.tsx        localStorage 저장·감사 로그·초기화 제공자
  data/use-mock-store.ts     화면 간 공유 데이터 접근
  lib/acl.ts                ACL 이름·목적지·포트 검증
  lib/format.ts             이름 마스킹 등 표시 규칙
  components/layout/        앱 셸(사이드바·헤더·테마), 페이지 헤더
  components/status-badge   상태·구분·결과 배지
  components/ui/            shadcn/ui 컴포넌트 (생성물, 직접 수정 지양)
  pages/                    화면별 컴포넌트
```

`vite.config.ts`는 배포 JS를 일반 스크립트(IIFE)로 묶고 CSS를 따로 생성합니다.
배포 HTML에는 `./index.js`와 `./index.css` 참조만 추가하며 앱 코드를 인라인으로 넣지 않습니다.

## 스택

Vite · React 19 · TypeScript · Tailwind CSS v4 · shadcn/ui · React Router · Recharts

**shadcn v4는 Radix가 아니라 [Base UI](https://base-ui.com) 기반입니다.** 컴포넌트를 추가할 때 주의할 점:

- `asChild` 대신 `render` prop을 씁니다 — `<Button render={<Link to="/x" />}>라벨</Button>`
- `Select`의 `onValueChange`는 `string | null`을 넘깁니다 — `(v) => setX(v ?? 'all')`
- 카드 헤더의 우측 액션은 `CardAction` 슬롯에 넣습니다

## 개인정보 표시 규칙

요구사항 §10에 따라 사용자 이름은 가운데를 마스킹해 표시합니다 (`김민수` → `김*수`).
엑셀 다운로드에서는 이메일·전화번호 등을 제외하고 계정·정책·만료 기한만 포함한다는 안내를
계정 목록 화면에 표시해 두었습니다. 실제 마스킹·제외 로직은 제품 구현에서 서버 측에 둡니다.

## 차트 색

shadcn 기본 `--chart-1..5`는 채도 0인 무채색 램프라 범주를 구분할 수 없어 교체했습니다.
라이트/다크 각각의 값은 `src/index.css` 하단에 있으며, 명도 밴드·채도 하한·색각 분리·대비 검사를
두 모드 모두 통과한 조합입니다. 색을 바꿀 때는 아래를 지켜 주세요.

- 범주 색 순서는 고정이며 순환시키지 않습니다.
- **파랑과 보라를 인접 배치하지 마세요.** 적록색약에서 거의 구분되지 않습니다(ΔE 0.4).
  막대 스택 순서를 바꿀 수 없는 이유가 이것이고, 그래서 합계를 축 라벨로 뺐습니다.
- 척도가 다른 지표는 축을 공유하지 않습니다. 전체 계정 수와 월간 신규·삭제를 별도 차트로 나눈 이유입니다.
