## 빌드 · 배포

목업은 서버 없이 동작하는 정적 파일이므로, 빌드한 결과물을 그대로 올리거나 전달하면 됩니다.

### 1. 빌드

```bash
cd mockup
npm install      # 최초 1회
npm run build    # 타입 검사 후 dist/ 생성
```

`dist/`는 `.gitignore`에 포함되어 있어 저장소에는 없습니다. 배포할 때마다 직접 빌드합니다.

### 2. 결과물

```text
dist/
  index.html
  index.js
  index.css
```

- 세 파일은 **반드시 같은 폴더**에 둡니다. HTML이 `./index.js`, `./index.css`를 상대 경로로 읽습니다.
- 폰트는 CSS에 포함되어 있어 별도 파일이나 외부 CDN이 필요 없습니다.

### 3. 배포 방법

| 방법 | 절차 |
|------|------|
| 파일 전달 | `dist/` 폴더째 전달하고, 받는 사람이 `index.html`을 더블클릭해서 엽니다. |
| 웹서버 | IIS, nginx, 사내 웹 호스팅 등에 `dist/`의 세 파일을 같은 폴더로 올립니다. |

- 서버에 Node.js나 별도 런타임은 필요 없습니다.
- 화면 이동은 해시 라우팅(`#/admins`)이라 서버의 URL 재작성 설정이 필요 없습니다.

### 4. 주의사항

- **데이터는 사용자별 브라우저에만 저장됩니다.** 서버에 올려도 다른 사용자·다른 브라우저와 공유되지 않습니다.
- **접속 주소가 바뀌면 저장 데이터도 새로 시작합니다.** 개발 서버(`localhost:5173`), 파일로 직접 연 경우, 배포 서버 주소는 저장소가 각각 별개입니다. 파일 위치를 옮겨도 마찬가지입니다.
- 저장 데이터를 비우려면 사이드바의 **목업 데이터 초기화**를 누르거나 브라우저 개발자도구의 Application → Local Storage에서 삭제합니다.
- 배포 후 빌드 파일을 교체했는데 이전 화면이 보이면 브라우저 캐시 때문일 수 있습니다. `Ctrl+F5`로 강력 새로고침합니다.
- 이 방식은 **화면 합의용 목업 배포에만 해당합니다.** 제품은 ASP.NET Core 백엔드와 DB가 필요하므로 별도로 배포합니다.

### 5. 디버깅

| 구분 | 방법 |
|------|------|
| 개발 (`npm run dev`) | 소스맵으로 원본 `.tsx`에 중단점을 걸 수 있습니다. React DevTools 확장으로 컴포넌트 상태도 볼 수 있습니다. |
| 배포 (`dist/index.html`) | 코드가 압축되어 있어 읽기 어렵습니다. Console 에러와 Network의 파일 로드 실패 확인용으로 씁니다. |

코드 디버깅은 개발 버전에서 하고, 배포 버전은 파일로 열었을 때 같은 동작인지 확인하는 용도로 씁니다.
