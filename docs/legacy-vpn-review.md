# Legacy VPN 회의 정리 — 프로젝트 범위·WBS·공수 산정

- **회의**: 2026-10-07 오전 10:00, Teams
- **목적**: RemoteHub 제안·수주 전 프로젝트 범위를 나누고 WBS와 공수 산정에 필요한 가정·미확인 사항을 정리한다.
- **근거**: [요구사항 초안](./00-requirements.md), 회의 메모 [`legacy-review.md`](./legacy-review.md)

이번 회의에서 기존 시스템을 실제로 충분히 점검하거나 운영 데이터·연동 데이터를 검증하지는 못했다. 아래 내용은 범위와 견적을 논의하기 위한 **잠정 입력**이며, 레거시 동작이나 구현 요건이 확정됐다는 뜻이 아니다. 실제 시스템 접근, 데이터 샘플 확인, 연동 방식 검증과 이관 대상 확정은 프로젝트 수주 후 착수 단계에서 수행한다.

## 회의에서 나온 단서

다음은 회의 메모에 적힌 내용이다. 구현 기준으로 사용하기 전에 담당자와 실제 환경에서 재확인해야 한다.

| 영역 | 회의 메모 | 산정에 미치는 영향·확인 사항 |
|---|---|---|
| 계정 수명 | 마지막 로그인 기준 1개월 미접속 계정 AD 삭제 언급 | 요구사항 초안 §7의 사용자 구분별 3개월·6개월·1년? 기준과 상충한다. 대상 계정, 기준일, 삭제 대상 시스템, 예외와 통보 절차를 확인해야 한다. |
| 계정 명명 | `VPN + 그룹사 코드 + 사번(숫자)` 형식 언급 | 그룹사 코드와 사번 원천, 중복·변경·기존 계정 처리 규칙 확인 필요 |
| ACL | 임직원은 그룹 ACL·AD OU, 협력사는 계정별 ACL로 메모 | 실제 적용 단위, 공유 ACL 변경 영향, 그룹사별 예외와 이관 범위 확인 필요 |
| MFA | 서드파티 OTP와 `M-PASS` 언급 | 관리자 로그인과 VPN 사용자 인증 각각의 적용 범위·연동 주체 확인 필요 |
| VPN 장비 | F5 BIG-IP 소프트웨어 `17.5.1.6`으로 메모 | 장비 모델·실제 버전·API 권한 및 지원 기능을 확인해야 연동 공수를 산정할 수 있다. |
| VPN·AD 연동 | VPN/AD 쪽 Tomcat 서버가 API를 제공하고, 소스 코드는 없다고 메모 | API 문서·호출 예시·소유자·오류 처리·테스트 환경과 변경 가능 범위 확인 필요 |
| AD | 그룹사별 AD attribute가 다르다고 메모 | 그룹사별 매핑 표, OU·`memberOf` 규칙, 계정 생성·삭제 권한 확인 필요 |
| 보안 | 암호화 방식·패스워드 정책 등 보안 요건이 있을 수 있다고 메모 | 보안 기준과 심사·승인 절차 확보 전에는 확정 공수로 보기 어렵다. |
| 일정 | `내년 4월~5월`이라는 메모가 있음 | 기준 연도, 목표 마일스톤과 납기 의미를 발주 측에 재확인해야 한다. |

신청 사용자 정보에 관한 메모도 있으나, 필드·출처·전달 방식은 기록만으로 확인할 수 없다.

## 범위·WBS 초안

아래 작업 묶음은 [요구사항 초안](./00-requirements.md)을 견적 단위로 나눈 것이다. 포함 여부와 상세 작업, 공수는 아직 확정하지 않았다.

| WBS 묶음 | 범위 검토 항목 | 공수 산정에 필요한 입력 |
|---|---|---|
| 착수·현행 분석 | 실제 운영 흐름, 레거시 화면·설정·데이터, 인터페이스, 권한·보안 제약 조사 | 접근 가능 환경·담당자, 자료 제공 범위, 현행 데이터 규모와 품질 |
| 요구사항·설계 | 업무 규칙 확정, 화면·권한·데이터 모델·연동 계약 설계 | 사용자 구분별 정책, 승인 흐름, 목업 피드백, 보안 기준 |
| 신청 연계 | EAI/API 수신, 신청 목록·엑셀 업로드, 요청 상태 및 중복·오류 처리 | 연계 필드·샘플·호출 주기, 신청 시스템별 차이 |
| VPN·ACL 연동 | 계정·정책·그룹 ACL 생성·변경·삭제, 결과 확인과 복구 | F5 및 중계 API 명세·권한, 기존 ACL 구조, 실패 시 재처리 기준 |
| AD·인증 연동 | 계정·OU·그룹·attribute 처리, 암호·MFA | 로그인 시 참조할 AD, 사용자 정보의 원천(신청 시스템 또는 타 AD), AD 간 실시간 연동 필요 여부, 그룹사별 매핑, Tomcat API/LDAP 역할, OTP·M-PASS 연계 범위 |
| 계정·IP 운영 | 계정 정책, 그룹사, IP 대역·고정 IP, 관리자 화면과 권한 | 실제 데이터 구조, 중복·할당·회수 규칙, 관리자 역할 |
| 배치·알림 | 접속 이력, 만료·미접속 처리, 재실행, 이메일 통보 | 삭제 기준 상충 해소, 로그 원천·주기, 메일 템플릿·발송 시스템 |
| 감사·보안·리포팅 | 변경·다운로드 기록, 개인정보·파일 암호화, 월간 통계 | 보관 기간, AIP Agent 제공 범위, 보고서 집계 기준 |
| 데이터 이관·검증·전환 | 이관 범위 정의, 정제·리허설, 연동/사용자 검증, 운영 전환 | 원천 데이터 샘플·건수·품질, 테스트 환경, 검수 기준·전환 방식 |

공수표를 만들 때에는 각 묶음을 설계·구현·연동 시험·사용자 검증·전환 작업으로 더 나누고, **확정 범위 / 가정 / 미정 범위**를 구별한다. 미확인 연동과 데이터 이관은 검증 전제와 변동 가능성을 견적에 명시한다. 현재 문서에는 근거 있는 작업량 수치가 없으므로 인일이나 금액을 기입하지 않는다.

AD 연동 방식은 [별도 메일 질의 초안](./ad-integration-email-questions.md)으로 확인한다. 답변에 따라 신청 연계와 AD 연동의 구현 범위·인터페이스 수·검증 공수가 달라진다. 실제 서버와 데이터의 상세 검증은 수주 후 수행한다.

## 범위 확정을 위한 후속 확인

| 우선 확인할 사항 | 확인 결과가 필요한 이유 | 확인 시점 |
|---|---|---|
| 발주 범위와 납기, 단계별 검수 기준 | WBS 포함/제외 및 일정·공수 기준 | 제안·계약 협의 |
| 신청 시스템·VPN·AD·MFA·메일 각 연동의 책임 주체와 제공 자료 | 외부 연동·테스트 공수와 의존 관계 | 제안 시 제공 가능 범위 확인, 상세 검증은 수주 후 |
| 로그인 AD와 사용자 정보의 원천, AD 간 실시간 연동 필요 여부 | 신청 연계와 AD 연동의 범위·공수 구분 | 메일로 먼저 질의, 상세 인터페이스는 수주 후 검증 |
| 미접속 삭제 정책과 그룹사별 예외 | 배치·알림·데이터 보존 범위 | 업무 담당자 확인 후 확정 |
| 이관 대상·기간·데이터 품질 및 운영 데이터 접근 | 이관·정제·검증 공수 | 수주 후 실제 데이터 확인 |
| 현행 API·서버·장비 설정과 테스트 환경 | 기술 실현성 및 연동 공수 | 수주 후 접근 권한 확보·검증 |
| 보안 정책, 암호화·MFA·AIP 기준 | 구현 및 보안 검증 범위 | 정책 자료 확보 후 확정 |

목업에 대한 별도의 이해관계자 리뷰와 수정 범위는 [PLAN.md](../PLAN.md)의 P0-16·P0-17로 관리한다. 이 레거시 회의만으로 그 작업이 완료되거나 제품 구현 범위가 확정된 것으로 처리하지 않는다.
